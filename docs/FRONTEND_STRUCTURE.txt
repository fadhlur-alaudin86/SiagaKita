  admin              | Administrator             | Desktop Console               | Superadmin

  agency_personnel   | Personel Instansi         | Mobile Responder (BARU)       | Agency (instansi)
  volunteer          | Relawan                   | Mobile Citizen App            | Daftar mandiri
  civilian           | Masyarakat Umum           | Mobile Citizen App            | Daftar mandiri

  PENTING (UPDATE):
  - "agency_responder" sudah TIDAK ADA — diganti dengan "agency" (akun instansi)
    dan "agency_personnel" (akun personel instansi).
  - Semua profil citizen/volunteer kini disimpan di tabel user_profiles (BUKAN users).
  - User dengan role admin/superadmin menyimpan nama di tabel admin_profiles.
  - User dengan role agency tidak punya tabel profil terpisah — namanya ada di tabel agencies.
  - User dengan role agency_personnel menyimpan data di tabel agency_personnels.

  ENDPOINT LOGIN SESUAI ROLE:
  - /auth/login           → civilian & volunteer (mobile citizen app)
  - /auth/console/login   → superadmin, admin, agency (desktop console)
  - /auth/personnel/login → agency_personnel (mobile responder app — BARU)

  Response API login:
  {
    "access_token":  "eyJ...",
    "refresh_token": "eyJ...",
    "user": {
      "id":        "uuid",
      "email":     "user@example.com",
      "role":      "civilian|volunteer|agency|admin|superadmin|agency_personnel",
      "full_name": "..." | null
    }
  }

  CATATAN: full_name diambil dari tabel profil yang sesuai.
  Untuk civilian/volunteer: dari user_profiles.
  Untuk admin/superadmin:   dari admin_profiles.
  Untuk agency_personnel:   dari agency_personnels.
  Untuk agency:             tidak dikembalikan (lihat data di tabel agencies).

3. ALUR NAVIGASI (Screen Flow — Mobile Citizen App)
===========================================================================

  [App Launch]
       │
       ▼
  LoginScreen
       │  → Email + Password → POST /auth/login  (hanya civilian/volunteer)
       │  → GPS Permission diminta
       │  → MainScreen (bawa accessToken + userId)
       │
       │  (Daftar di sini)
       ▼
  RegisterScreen — 2 Langkah
    Step 0: Nama + Email + Password (dengan strength bar)
            → POST /auth/register → Kirim OTP ke email
    Step 1: Input OTP 6 digit (resend cooldown 60s)
            → POST /auth/verify-register-otp → JWT
            → GPS Permission diminta
            ↓
       BiodataScreen (menerima accessToken + userId)
         - Golongan darah, BB, TB, riwayat medis, alergi
         - Alamat, kontak darurat
         - Data disimpan ke user_profiles (BUKAN users)
         ↓
  MainScreen (bawa accessToken + userId)

  [Berdasarkan role dari JWT]
    ├── civilian/volunteer → MainScreen (Beranda/Panduan/Map/Profil)
    │     └── HomeScreen (dengan GPS tracking SOS)
    └── role lain → Tampilkan error "Gunakan aplikasi yang sesuai"

  [Verifikasi Nomor HP — dalam ProfileScreen, setelah login]
    Isi nomor HP → POST /users/phone/request-otp → OTP via WhatsApp
    Input OTP → POST /users/phone/verify-otp → is_phone_verified = true di user_profiles

─────────────────────────────────────────────────────────────
4.1 LOGIN SCREEN (features/auth/login_screen.dart)
─────────────────────────────────────────────────────────────
  Status: ✅ TERHUBUNG KE API

  PENTING: Endpoint ini HANYA untuk civilian dan volunteer.
  Jika role lain mencoba login, backend mengembalikan error 401.

  Flow:
    1. Validasi form lokal
    2. POST /auth/login → return JWT langsung
    3. LocationService.requestPermission() — minta izin GPS
    4. Navigate ke MainScreen dengan accessToken + userId

  API:
    POST /api/v1/auth/login
    Body:  { "email": "...", "password": "..." }
    Response 200: { "access_token": "...", "refresh_token": "...", "user": {...} }
    Response 401: { "message": "akun ini bukan akun masyarakat atau relawan" }

─────────────────────────────────────────────────────────────
4.2 REGISTER SCREEN (features/auth/register_screen.dart)
─────────────────────────────────────────────────────────────
  Status: ✅ TERHUBUNG KE API

  STEP 0 — Form Data Akun:
    Field: full_name, email, password (min 8 kar), repeat_password
    Password Strength Bar — 3 segmen animasi
    Resend OTP countdown: 60 detik

  PERUBAHAN BACKEND: Register kini membuat 2 baris secara transaksi:
    1. INSERT INTO users (email, password_hash, role='civilian')
    2. INSERT INTO user_profiles (user_id, full_name)
    Rollback keduanya jika SMTP gagal kirim OTP.

  API:
    POST /api/v1/auth/register
    Body: { "full_name": "...", "email": "...", "password": "..." }
    Response: { "message": "OTP dikirim ke email", "email": "..." }

  STEP 1 — Verifikasi Email OTP:
    POST /api/v1/auth/verify-register-otp
    Body: { "email": "...", "otp_code": "123456" }
    Response: { "access_token": "...", "refresh_token": "...", "user": {...} }

  CATATAN: Nomor HP TIDAK dikumpulkan saat register.
  HP dikumpulkan + diverifikasi di halaman Profile/Biodata.

5. RINGKASAN ENDPOINT API (DIPERBARUI)
===========================================================================

  ★ = Sudah terhubung ke Flutter
  ○ = Belum terhubung

  AUTENTIKASI (public)
  Method | Endpoint                           | Status | Keterangan
  -------|------------------------------------|---------|---------------------------------
  POST   | /api/v1/auth/register              | ★      | Buat akun civilian → kirim OTP
  POST   | /api/v1/auth/verify-register-otp   | ★      | Verifikasi OTP → JWT
  POST   | /api/v1/auth/login                 | ★      | civilian/volunteer → JWT
  POST   | /api/v1/auth/console/login         | —      | admin/agency/superadmin → JWT
  POST   | /api/v1/auth/personnel/login       | —      | agency_personnel → JWT (App baru)
  POST   | /api/v1/auth/request-otp           | ★      | OTP WA (phone verification)
  POST   | /api/v1/auth/verify-otp            | ★      | Verifikasi OTP WA

  PROFIL USER (protected — civilian/volunteer only)
  Method | Endpoint                           | Status | Keterangan
  -------|------------------------------------|---------|---------------------------------
  GET    | /api/v1/users/profile              | ○      | Profil dari user_profiles
  POST   | /api/v1/users/biodata              | ○      | Update user_profiles
  POST   | /api/v1/users/phone/request-otp    | ○      | OTP WA ke HP baru
  POST   | /api/v1/users/phone/verify-otp     | ○      | Konfirmasi OTP HP

  INSIDEN (protected — semua role)
  Method | Endpoint                           | Status | Keterangan
  -------|------------------------------------|---------|---------------------------------
  GET    | /api/v1/incidents/active           | ★      | Cek SOS aktif
  POST   | /api/v1/incidents/trigger          | ★      | Kirim SOS
  POST   | /api/v1/incidents/:id/cancel       | ★      | Batalkan SOS
  PUT    | /api/v1/incidents/:id/location     | ★      | Update GPS tiap 1 menit
  POST   | /api/v1/incidents/:id/mark-false-alarm | —  | [ConsoleOnly] Tandai false alarm
  POST   | /api/v1/incidents/:id/resolve      | —      | [ConsoleOnly] Selesaikan insiden

  LAPORAN WARGA — JALUR B
  Method | Endpoint                           | Status | Keterangan

6. SKEMA DATABASE — TABEL TERKAIT MOBILE CITIZEN APP
===========================================================================

  users
    id, email, password_hash, role, created_at, deleted_at
    → Hanya kredensial. TIDAK ada nama, HP, dsb.

  user_profiles
    user_id (FK→users), full_name, nik, date_of_birth, phone_number,
    is_email_verified, is_phone_verified, is_verified_volunteer,
    sos_strike_count, is_sos_banned, banned_until,
    blood_type, allergies, medical_conditions, height_cm, weight_kg,
    alamat, updated_at
    → Profil lengkap civilian & volunteer. Dibuat bersamaan dengan users (transaksi).

  emergency_contacts
    id, user_id (FK→users), contact_name, contact_phone, relation, created_at

  volunteer_certifications
    id, user_id, certificate_type, document_url, status, verified_by, expires_at

  volunteer_reputation
    user_id, exp_points, rank_id, total_rescues, updated_at

  sos_strikes
    id, user_id, incident_id, reason, marked_by, created_at
    → Audit log setiap false alarm. Jumlah strike dibaca dari user_profiles.sos_strike_count.

7. CATATAN TAMBAHAN UNTUK BACKEND & TIM BARU
===========================================================================

  1. ROLE VALUES (TERBARU): superadmin | admin | agency | agency_personnel |
     volunteer | civilian. "agency_responder" sudah dihapus.

  2. TABEL USERS SLIM: Jangan query nama, HP, atau data profil dari tabel users —
     tabel ini hanya berisi auth credentials. Semua data profil ada di user_profiles.

  3. REGISTER TRANSACTION: Register() membuat users + user_profiles dalam 1 transaksi.
     Rollback keduanya jika pengiriman OTP gagal.

  4. DOCKER SERVICE: Nama service di docker-compose.yml adalah "backend".
     Deploy: sudo docker compose -f infrastructure/docker-compose.yml up --build -d backend

  5. GPS FORMAT: Koordinat dalam Double (desimal). Backend menerima latitude + longitude.

  6. SOS POLICY: Pengguna yang belum verifikasi HP (is_phone_verified=false) TETAP
     bisa kirim SOS. Dashboard console menampilkan flag "IDENTITAS BELUM TERVERIFIKASI".

  7. SUPERADMIN AUTO-SEED: Setiap server start, backend mengecek keberadaan akun
     superadmin dari SUPERADMIN_EMAIL dan SUPERADMIN_PASS di .env.
     Jika belum ada, dibuat otomatis. Jika sudah ada tapi env berubah, diperbarui.

  8. MOBILE RESPONDER APP (agency_personnel): Aplikasi Flutter baru yang belum dibuat.
     Akan ada di folder mobile-flutter-responder/. Fitur: lihat dispatch, update status,
     GPS real-time. TIDAK bisa kirim SOS atau laporan warga.

  9. LOKALISASI (ID/EN) dikelola frontend-side via ValueNotifier. Tidak butuh API.
